# Reproducing tests
Run dotnet test tests/Wholesale.Tests from Assignment2: 26 meaningful business-rule, password and local assistant tests.
Run dotnet run --project tests/Wholesale.IntegrationTests -- <absolute Assignment2 folder> for 45 MSSQL checks. Add `--browser` while the portal is running to execute the 46th check: Chrome signs in as an isolated test agent, orders two products, confirms the demo payment, verifies My Orders and the printable invoice, and checks the 304px layout. This opt-in executable reads the configured classroom DB, creates uniquely named fixture agents/users/items/orders, briefly installs a trigger that fails only on its own test item, and removes its fixtures/trigger in finally. Baseline and final table counts are compared. Payment checks include a single-product invoice, owner-only confirmation, idempotent retry, Paid timestamp/reference, My Orders status and cancellation/refund stock restoration. Invoice checks also cover the registered agent's print contact. Fixture checks now include company editing and safe product deactivation.
Results are saved in docs/evidence/integration-results.txt and .json. Domain test TRX files are copied into docs/evidence by the packaging step.
The browser demo created one Arabica order (#55, 245,000 VND) and confirmed its classroom-only payment. This visible example remains in the classroom database and consumes one unit of stock; no real payment is processed.
For repeatable browser and print inspection, start the portal and run `tools/verify-portal-ui.cjs` with Playwright and Chrome available. By itself, it checks sign-in, catalog, an existing paid invoice, 304px layout, browser errors, and exports the invoice plus the synthetic shipping-manifest fixture to A4 PDF without modifying an order. The `--browser` integration mode supplies temporary credentials and product IDs to the same script; its created order is removed by the SQL harness.

The expanded browser script verifies 33 public/Agent controls on the seeded account, or 32 plus an isolated two-line checkout and payment when called by the integration harness. From the workspace root, `Run-Demo.ps1 -App Test -BrowserTest -ButtonTest` runs both unit suites, both SQL harnesses, Chrome checkout and native button audits while the portal serves at `PORTAL_URL`. The native Admin audit opens add/edit/details dialogs and closes them without saving; SQL fixtures verify changes, cancellation, status, rollback and stock safety. On the local SQLEXPRESS instance, AUTO_CLOSE is disabled by both setup scripts to prevent repeated database recovery. Printed PDFs are inspected; a physical printer is outside this automated check.
